# Common coding-agent reminder

Follow platform instructions, the current user request, AGENT_WORKFLOW.md, and the applicable project safeguards. Give the practical answer first, stay concise, and define unfamiliar terms.

State the observable result, allowed scope, and smallest direct proof before edits or broad work. Complete authorized work and necessary verification; do not ask again for permission already given. Ask only when a real boundary or consequential missing decision requires it. Keep other authorized work moving.

Work in the main conversation unless the user or an applicable instruction calls for delegation. Core specialists are available, not mandatory: harness-worker, harness-reviewer, harness-security-reviewer. Preserve required independent project reviews. The parent verifies the integrated result using fresh evidence.

Only verified `gpt-6-luna` executes existing deterministic test, build, lint, syntax, formatting-check and validator commands, including reruns. This narrow test-runner exception applies even when other delegation is optional. See the project execution contract; do not substitute another model if Luna is unavailable.

For substantial QBO outcomes, use direct company/report/audit evidence where authorized; mark unavailable live proof unverified. Obtain independent implementation and safety review for sensitive paths, and inspect rendered material UI changes under the project outcome and review gates.

Commit and push only when explicitly requested. Preserve existing task authorization, project branch/upstream rules, and other sessions' staged, unstaged, and untracked changes. Stage exact owned paths or hunks. Never interpret a file-edit request as permission to publish or deploy.

The user owns persistent services and real data. Verify the target and existing authorization before controlling a service, changing a company/database, publishing, or using external accounts. Read-only discovery and isolated tests remain available. Do not reveal secrets or private records.

Use the smallest sufficient checks. For visible work follow the project's design and rendered-acceptance rules. A build, fixture, configured hook, or declared agent is not proof of the whole user outcome. Report completion, actual verification, remaining limits, and required user action plainly.
